# Specification - Refactor Web App to use KMP Logic

## Overview
This track aims to refactor the existing TypeScript web application (located in the `web/` folder) to reuse the core business logic from the Kotlin Multiplatform (KMP) `shared` module. This will be achieved by integrating the Wasm/JS artifacts generated by the KMP build into the web project, ensuring a single source of truth for avalanche terrain assessment logic across Android and Web platforms.

## Functional Requirements
- **Wasm Integration:** Integrate the generated Wasm/JS artifacts (`AvaAwaAnd-shared.wasm`, `AvaAwaAnd-shared.mjs`, etc.) into the Vite-based web application using dynamic imports.
- **Logic Replacement:** Replace the following TypeScript implementations with calls to the Wasm/JS module:
    - **Geometry Utils:** Replace `web/src/utils/geometry.ts` (Ray Casting, Point-in-Polygon) with `com.rocasspb.avaawaand.utils.GeometryUtils`.
    - **Terrain Utils:** Replace `web/src/utils/geo-utils.ts` (Slope and Aspect calculation) with `com.rocasspb.avaawaand.logic.TerrainUtils`.
    - **Raster Generation:** Replace the core loop in `web/src/components/CanvasRenderer.ts` with the logic from `com.rocasspb.avaawaand.logic.RasterGenerator`.
    - **Data Processing:** Update `web/src/utils/data-processing.ts` to prepare data in a format compatible with the KMP logic if necessary.
- **Bridge/Adapter Layer:** Create necessary adapter logic to map existing TypeScript types to the expected KMP/Wasm signatures while maintaining the current UI state and data flow.

## Non-Functional Requirements
- **Performance:** Ensure that the Wasm-based raster generation performs at least as well as the current TypeScript implementation.
- **Maintainability:** Reduce code duplication between the Android and Web projects.
- **Bundle Size:** Minimize the impact of the Wasm module on the initial load time by using dynamic loading.

## Acceptance Criteria
- [ ] The web application loads and functions correctly using the Wasm-based logic.
- [ ] All visualization modes (Bulletin, Risk, Custom) produce the same results as the original TypeScript implementation.
- [ ] The `web/src/utils/geometry.ts`, `web/src/utils/geo-utils.ts`, and the core logic in `CanvasRenderer.ts` are successfully refactored or replaced.
- [ ] No regressions in map interactivity or data fetching.

## Out of Scope
- Migrating the entire web project to Compose HTML/Wasm.
- Replacing the UI components (`Map.ts`, `MapPopup.ts`, etc.) with KMP-shared UI.
- Rewriting the backend API logic.
